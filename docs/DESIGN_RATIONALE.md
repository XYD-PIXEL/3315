# 从 Part I 到原型

范围来源是小组提供的 Part I，而非额外产品设想。项目说明作为课程交付背景：Task 6 要求至少三个用户任务、Figma 交互原型、三位组外典型用户及问题记录。没有把附件中的会议安排等内容作为执行指令，也没有访问附件内的问卷或个人文档链接。

## 设计选择

| Part I 依据                            | 原型实现                             | 需要验证的假设                       |
| -------------------------------------- | ------------------------------------ | ------------------------------------ |
| 18/19 曾不确定如何分类                 | 物品名与垃圾桶结果一起出现           | 能否确认识别的物品正确               |
| 47.4% 觉得混合材料包装最难             | 咖啡杯候选、内衬说明、薯片包装搜索   | 短描述是否帮助区别相似物品           |
| 57.9% 认为速度非常重要，31.6% 认为重要 | 直达扫描，没有账号、欢迎页或标签导航 | 整条流程是否在短时间内完成           |
| 忙碌、单手、站在垃圾桶旁               | 大按钮、底部主要操作、三张候选卡     | 持物品时能否点击准确                 |
| 结果需明确且与实际桶对应               | 桶图标、类别文字、颜色共同编码       | 真实颜色匹配尚需实地验证             |
| 模型可能不确定                         | 候选、无匹配、搜索、搜索空状态       | 用户是否知道下一步可以做什么         |
| QR 编码站点                            | `station` 参数与无效站点错误         | 用户能否确认当前站点；不误用别处规则 |
| 处理提示要简短                         | 单独的 Before you drop it 卡片       | 用户是否注意并能复述处理要求         |
| AI 在项目中模拟                        | 三个固定、可重复的演示情境           | 只能评估界面，不能评估识别准确率     |

## 信息和视觉层级

工作流为 scanner → matching → result / candidates / unknown → result → complete。搜索在扫描、候选、识别失败和结果页都有入口。没有新增持久账号、历史、积分或地图导航。

使用淡色背景和深绿色动作按钮；结果卡按类别使用黄色、珊瑚色和绿色，始终保留文字与图标。色彩只用于交互设计演示，不能声称是某所学校的真实颜色规范。核心扫描、搜索和候选操作按手机尺寸提供大点击区域；次要文本按钮仍需在单手实测中检查。

默认使用样例画面，减少相机设备差异对界面评估的干扰。`camera=live` 能演示扫码后立即请求权限。可选实际相机仅做本地预览。模拟识别延迟固定为 750 ms，不代表真实模型性能。

页面采用英语，与课程材料语言一致；运行及主持人说明用中文。三种演示场景与八条示例规则集中在 `src/data.ts`，后续可替换经设施部门确认的内容。

## 明确的边界

- 校园设施方没有确认示例规则、垃圾桶颜色、编号或位置。
- 无图片分析、后台、图片上传、定位权限、个人数据采集或任务表现自动记录。
- 食物垃圾缺少对应桶时不会强行建议使用其他桶。
- 搜索无结果时不捏造分类，提醒核对桶标签或询问设施部门。
- 小额退瓶功能只是附属信息展开，不包含真实点位、距离、退款资格判断或服务跳转。
- 电脑侧边栏和手机下方场景选择是主持人控件。参加者任务应使用预设情境，由主持人设定。
